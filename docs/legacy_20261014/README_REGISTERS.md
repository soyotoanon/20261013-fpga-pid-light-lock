# README_REGISTERS.md —— 光强锁定主工程（adc_pi_loop）寄存器手册

本文档对应 RTL：`rtl/reg_file.v`（64 × 16 位寄存器堆）。
上位机工具：`host/llctl.py`。烧录固件：`bitstream/light_lock_top.bit`。

---

## 1. 通信链路

| 项 | 值 |
|---|---|
| 物理链路 | 板载 Type-C 串口（**不用飞线**） |
| FPGA 引脚 | `uart_rx = U5`（FPGA 收）、`uart_tx = T6`（FPGA 发） |
| 波特率 | 115200，8N1，无流控 |
| 分频寄存器 | `0x29 BAUD_DIV`，默认 `434`（= 50 MHz / 115200） |
| 写帧格式 | `C5 01 <addr> <dataL> <dataH> 5C C5 C5`（**定长 8 字节**） |
| 读帧格式 | `C5 02 <addr> 00 00 5C C5 C5`（同样 8 字节，应答在 `byte_idx==7` 才发出） |

写帧由 `rtl/uart_proto.v` 解析；地址 6 位、数据 16 位小端。

**★★ 帧长必须是 8 字节（本次自查修正）**：`uart_proto.v` 是**定长 8 字节**状态机，`byte_idx`
是 3 位、数到 7 才回卷。此前 `host/llctl.py` 与本手册都按 **6 字节**写，后果是：
- **写命令只有每隔一帧生效一条** —— RTL 停在 `byte_idx==6`，把下一帧的头两个字节当成第 7/8 字节
  吃掉，再下一帧才重新对齐；
- **读命令永远到不了 `byte_idx==7`，读回恒为空**。

尾部两个 `C5` 目前**不参与校验**（只有第 5 字节的 `5C` 被检查），但必须补齐，否则字节对齐会一路错下去。
（回归基准 `tb/tb_light_lock.v` 一直发的是 8 字节，所以"22 项全过"只证明了 testbench 通路本身是通的。）
**注意**：`BAUD_DIV` 改错会导致整条串口失联，改完必须按新波特率重连。

## 2. 两个时基（决定所有波形的频率）

### 2.1 ADC 采样时钟 —— `0x11 ADC_HALF`

```
ADC 周期 = 2 × (ADC_HALF + 1) × 20 ns        // sys_clk = 50 MHz ⇒ 20 ns
```

| ADC_HALF | ADC 周期 | ADC 频率 |
|---|---|---|
| 0 | 40 ns | 25 MHz |
| 4 | **200 ns** | **5 MHz**（默认） |
| 9 | 400 ns | 2.5 MHz |
| 24 | 1 µs | 1 MHz |

> ★ 要 5 MHz 必须写 **4**，不是 5。`rtl/adc_drv.v` 里 `div_cnt` 复位为 0，
> 所以首拍即翻转，实际周期是 `2×(half+1)` 拍。

### 2.2 控制节拍 —— `0x10 CTRL_HALF`

```
控制周期 = 2 × (CTRL_HALF + 1) × 20 ns
```

默认 `499` ⇒ 2×500×20 ns = 20 µs ⇒ **50 kHz**。PI 控制、DAC 波形推进、统计窗口、
扫描步进、光丢失判定全部挂在这个节拍上。

> ★ 注意那个系数 **2**。`rtl/ctrl_tick.v` 用 `phase` 的非阻塞赋值**前值**判断
> （`if (phase) tick <= 1'b1;`），复位后 `phase=0`，所以第一次 `cnt==0` 不发 tick、
> 第二次才发 ⇒ 一个完整控制周期跨**两个**半周期。
> 实测交叉验证：`half=4` 时 200000 个 `sys_clk` 内恰好 20000 个 tick（10 拍/tick），
> 与 `2×(4+1)=10` 吻合。
> `CTRL_HALF` 是 16 位寄存器，上限 65535 ⇒ 最慢约 2×65536×20 ns ≈ **2.62 ms**。
> （2026-10-14 第三轮审查改：原文写成 1.31 ms，漏了那个系数 2。）

## 3. 地址表

R = 只读，W = 可写，RW = 可读写。「默认」列是 FPGA 上电（或复位）后的值，
由 `reg_file.v` 的 `default_value` 函数给出（**可综合**，不是 initial 块）。

> ⚠ **只读地址没有写保护**（第四轮自查确认）：`rtl/reg_file.v:139-141` 对**任意**地址都执行
> `mem[addr] <= wdata`。写 `0x01`/`0x03`–`0x09`/`0x2A` 只会写进那些**永远不会被读出**的
> mem 槽位（读通路 `:147-190` 对这些地址返回实时值），写 `0x2B`–`0x3F` 同样读回 0。
> 所以效果上等价于"忽略这次写"，但**不是**被硬件拦住——手册说"只读"是就**读回值**而言。

### 3.5 PI 闭环（【13】【16】）

| 地址 | 名称 | R/W | 默认 | 说明 |
|---|---|---|---|---|
| `0x18` | `SETPOINT` | RW | `0x2000` | 目标光强（ADC 码域） |
| `0x19` | `BIAS_CODE` | RW | `0x2000` | 静态偏置工作点 |
| `0x1A` | `KP_SHIFT` | RW | `6` | 比例增益右移位数（5 位有效） |
| `0x1B` | `KI_SHIFT` | RW | `12` | 积分增益右移位数（6 位有效；**有效范围 0..22**，RTL 内部钳到 22——再大时积分步长会塌成 0/−1，见 §3.5） |
| `0x1C` | `I_CLAMP_LO` | RW | `0x0000` | 积分限幅低 16 位 |
| `0x1D` | `I_CLAMP_HI` | RW | `0x0020` | 积分限幅高 16 位 ⇒ 默认 `32'h00200000` |
| `0x1E` | `OUT_MIN` | RW | `0x0000` | 输出下限 |
| `0x1F` | `OUT_MAX` | RW | `0x3FFF` | 输出上限 |
| `0x20` | `DIR_POL` | RW | `1` | 方向极性（光强增 ⇒ 输出增/减） |
| `0x2A` | `I_VALUE` | R | — | 积分器当前值的**低 16 位**（2⁻⁹ 码单位，只看趋势） |

> **⚠️ `I_CLAMP` 和 `I_VALUE` 的单位是 2⁻⁹ 码**（积分器内部多带 9 位小数）：
> 默认 `I_CLAMP = 32'h0020_0000 = 2097152`，除以 2⁹ ⇒ 积分最多贡献 **±4096 码**
> （满量程 16384 的 1/4）。想限制到 ±1000 码就写 `1000 × 512 = 512000 = 0x0007_D000`。
> `rtl/pi_ctrl.v` 里的表达式两边是自洽的：积分步长含这 9 位（`(e <<< 9) >>> KI_SHIFT`），
> 输出前再 `>>> 9` 还原成码。
> 另外 `I_VALUE` **只回读低 16 位**，积分超过 65535（约 128 码）后就会回卷；
> 想知道有没有到限请读 `STATUS` 的 bit3（`i_at_limit`），别拿 `I_VALUE` 当绝对值用。

PI 律（`rtl/pi_ctrl.v`）：

```
e[n] = sp - y                    // 码域，有符号
u[n] = bias + ((Kp·e[n]) >> KP_SHIFT) + (I[n] >>> 9)
I[n+1] = clamp(I[n] + ((e[n] <<< 9) >>> KI_SHIFT), ±I_CLAMP)
out  = clamp(u[n], OUT_MIN, OUT_MAX)
```

（`I[n]` 与 `I_CLAMP` 都是 **2⁻⁹ 码**单位；`KI_SHIFT` 在 RTL 里被钳到 ≤22，见上表。）

> ★ **第四轮闭环仿真发现并修复的真缺陷**（`rtl/pi_ctrl.v:122-135`）：原抗饱和逻辑里
> `i_hold` 只挡住"继续朝饱和方向累加"，却**同时挡住了积分回到钳位以内**。于是运行时把
> `I_CLAMP` 调小、而误差仍是同号时，积分会永远停在旧的大值上 —— 实测把 `0x0100_0000`
> 写回默认 `0x0020_0000` 后，闭环平台仍是 `0x3A7A`，而按新钳位应只有 `0x303F`。
> 现已改成 hold 分支也做硬钳位 ⇒ **`|I[n]| ≤ I_CLAMP` 任何时刻都成立，调小立即生效**。
> 另外记住：调小钳位后积分是**被硬拉回**边界的（不是逐步退回），所以输出那一下会跳。

`Ki·Ts` 在 FPGA 内合并成一个离散积分增益，所以上位机不需要知道 Ts。

## 4. 位定义与使用要点

### 4.1 `CTRL`（0x00）

| 位 | 名称 | 说明 |
|---|---|---|
| `[0]` | 使能 | PI 闭环总开关 |
| `[1]` | **ADC 直通** ⚠ | 1 = 把 ADC 采样码**原样**送 DAC（RTL：`wire passthrough = ctrl[1];` → `code_sel = adc_sample`），PI、波形、扫描全被绕过。<br>**不是**"输出固定 `DAC_CODE`"——固定码是 `[3:2]=2`。 |
| `[3:2]` | 模式（DAC 数据源） | `0` = PI 闭环输出 / `1` = 信号发生器 / `2` = 固定码 `0x14`（`SIG_FIXED`）/ `3` = 自动扫描<br>⚠ 写 `0x12` 是 **`SIG_EN`**，别把固定码写进去（第四轮自查更正） |
| `[4]` | 装订积分与偏置 ★ | **电平**：写 1 期间积分器恒被清零、输出被压回 `BIAS_CODE`（"从这里开始调"），用完必须写回 0 |
| `[8]` | 清积分 | 只清积分器，不动输出 |
| `[9]` | 清标志 | 清 `light_lost` / `otr_seen` / `out_sat_seen` / `loss_run`（`frozen` 与 `loss_cnt` **不清**） |
| `[10]` | 清统计 | 清均值/方差/极值窗口（第二轮自查前是**死位**：`adc_stats` 没有 `clr` 端口；现已新增 `clr` 并接上，同时清零累加器与 min/max） |
| `[12:11]` | 调试 LED 输出字节选择 | 选择 `led_status` 上送哪个字节 |

**★ 本次自查修正的两点**

1. **模式位是 `[3:2]`，`[2]` 不是独立功能位。** 顶层 `wire [1:0] mode = ctrl[3:2]`，而
   `[3:2]==0` 恰好就是 PI 闭环。想切到信号发生器要写 `[3:2]=1`；单写 `[2]=1` 会
   **同时把模式变成 1**，PI 与统计监视一起停掉。
2. **`[4]`（装订）是本次改出来的新位。** 这个功能原来接在 `[2]` 上，与模式位冲突 ⇒
   PI 使能时它恒为 0，等于**根本不存在**（`pi_ctrl` 里那段是死代码）。现改到 `[4]`。
   用法是**先写 1、再写回 0** —— 它是电平不是自清脉冲。

`[9]` 清的是"粘滞"类标志；`frozen`（冻结）与 `loss_cnt`（累计暗计数）**故意不清**，
它们是"曾经发生过光丢失"的证据。另：`out_sat_seen` 会被 `[9]` 清零，但**没有上送到任何寄存器**，
STATUS 里看不到它（见 4.2）。

### 4.2 `STATUS`（0x01，只读）

| 位 | 名称 | 说明 |
|---|---|---|
| `bit0` | 光丢失 | 连续低于 `LIGHT_TH` 达阈值次数 |
| `bit1` | OTR | AD9248 溢出粘滞位 |
| `bit2` | 输出到限 | `out_code` 被 `OUT_MAX`/`OUT_MIN` 限幅（**实时电平**，非粘滞） |
| `bit3` | 积分到限 | 积分器被限幅（**实时电平**，非粘滞） |
| `bit4` | 冻结 | 光丢失 ⇒ 整环冻结（输出保持） |
| `bit5` | ADC 时钟停摆 | ADC 时钟检测失效 |
| `bit6` | 扫描完成 | 自动扫描跑完一轮 |

### 4.3 `SWEEP_CTL`（0x0F）

`[0]` 使能、`[1]` 连续模式、`[2]` 启动。
`[2]` 也是**电平**：置 1 后要清掉才会重新触发下一次。

### 4.4 ★ 「电平位」不是脉冲位（踩过两次的坑）

`SIG_EN[1]`（update）、`DIST_EN[1]`（update）、`CTRL[9]`（清标志）、
`SWEEP_CTL[2]`（启动）在 RTL 里都是**电平信号**，不是写一次就自清的脉冲。

- **update = 1 会每拍把相位/计数清零**。如果写完不管，波形永远不动
  （实测：`phase` 在 4000 拍里恒 0，输出恒 `0x2000`）。
  正确做法是**先给 update、再把它清掉、只留 enable**：

  ```
  write_reg(0x12, 0x0003)   # enable + update ⇒ 复位相位/计数
  delay(...)
  write_reg(0x12, 0x0001)   # 只留 enable ⇒ 相位开始推进
  ```

- **清标志位 = 1 会每拍把计数器清零**。写 `CTRL=0x0201` 清完标志后
  必须放掉 bit9（改回 `0x0001`），否则 `loss_run` 永远累不到阈值、
  `light_lost` 永不置位（实测 `loss_run` 恒在 0↔1 之间跳）。

`host/llctl.py` 的 `pulse_ctrl_bit()` 已封装这个用法，建议直接用它。

### 4.5 `SIG_MODE`（0x13）波形选择

| 值 | 波形 |
|---|---|
| `0` | 固定码（用 `SIG_FIXED`） |
| `1` | 方波 |
| `2` | 阶跃 |
| `3` | 锯齿 |
| `4` | 三角 |
| `5` | 正弦 |

波形频率 = 控制节拍频率 / `SIG_PERIOD`。默认 50 kHz / 1000 = **50 Hz**。
（`SIG_PERIOD` 的有效下限是 16。**第三轮审查改**：小于 16 时 `dac_sig_gen.v` 给相位加的是
`21'd1048576`＝2²⁰，而相位寄存器只有 20 位 ⇒ 加法被截断、相位**原地不动**，波形是**恒定直流**，
不是原文写的"整圈跳"。想要极慢波形请把 `SIG_PERIOD` 取 16..1000，或改用 `DIST_PERIOD` 扰动。）

### 4.6 `DIST_MODE`（0x24）扰动波形

| 值 | 波形 |
|---|---|
| `0` | 关（delta 恒 0） |
| `1` | 阶跃（4 拍后跳） |
| `2` | 方波 |
| `3` | 正弦（默认） |
| `4` | 三角 |

扰动只叠加到**设定值**上（`r = clamp(SETPOINT + delta)`），不动反馈支路。

**周期口径（2026-10-14 自查统一）**：一圈 = `DIST_PERIOD` 个控制周期，
阶跃/方波/正弦/三角四种波形完全一致，与 `dac_sig_gen` 的口径也一致。
控制周期默认 `2×(CTRL_HALF+1) = 1000` 个 `sys_clk` = 20 µs ⇒
`DIST_PERIOD=4096` ⇒ 一圈约 **82 ms**（≈12 Hz）。

**幅度口径（同一次自查统一）**：`DIST_AMP` 就是**峰值**，四种波形都按峰值处理；
写 > `0x7FFF` 会被夹到 `0x7FFF`（避免 16 位无符号值在高半区被当成负数）。

> ★ 改前的两个 bug（都已修，回归见 `tb/tb_step_gen.v`，18 项断言）：
> ① 正弦/三角的相位**只在 `DIST_PERIOD` 边界推进一次**、步长 `65536/DIST_PERIOD`，
>    实际周期是 `256 × DIST_PERIOD²`（对 `DIST_PERIOD` 是**平方**关系），
>    而同一模块的方波却是 `DIST_PERIOD` 拍。`DIST_PERIOD=4096` ⇒ 正弦一圈约
>    **16 天**，等于"开了正弦跟没开一样"（`DIST_MODE` 默认就是 3=正弦）。
> ② 正弦走的是**非奇函数**的四次多项式（含 t²、t⁴ 偶次项），代入定点标度实算
>    正峰 +2086 / 负峰 −4746（±2048 标度）⇒ 正负半周严重不对称；
>    而且峰值只有 `DIST_AMP/16`，与方波/阶跃差 16 倍。
> 现在正弦/三角改用**与 `dac_sig_gen` 共用的查表** `rtl/sin_lut.vh`
> （Q15、64 项四分之一波表 + 象限折返），相位每 tick 推进 `2^24 / DIST_PERIOD`。

## 5. 常用操作（对应 21 项功能）

| 功能 | 操作 |
|---|---|
| 【05】读写参数 | 任意 `write_reg` / `read_reg` |
| 【04】DAC 测试信号 | **先写 `CTRL[3:2]=1`**（`0x00 = 0x04`，否则波形进不了 DAC——`code_sel` 只在模式 1 时选信号发生器）；再写 `0x13` 选波形、`0x15/0x16/0x17` 设幅度/偏置/周期，最后按 §4.4 写 `0x12` |
| 【12】设目标光强 | 写 `0x18 SETPOINT` |
| 【13】开 PI | 写 `0x1A/0x1B` 定增益，`CTRL[0]=1` |
| 【16】在线调参 | 运行中直接改写 `0x1A/0x1B/0x1C/0x1D`，立即生效 |
| 【15】清保护 | 写 `CTRL=0x0201`，**随后放掉 bit9** |
| 【07】自动扫描 | **先写 `CTRL[3:2]=3`**（`0x00 = 0x0C`，否则扫描码进不了 DAC）；再写 `0x0A/0x0B/0x0C/0x0D/0x0E`，最后写 `0x0F` 启动（`host/llctl.py: start_sweep()` 已封装） |
| 【09】读噪声统计 | 读 `0x06 MEAN` / `0x07 VAR_Q4`（真值 = `VAR_Q4 / 16`） |
| 【17】阶跃扰动 | 写 `0x24=1`、`0x25` 幅度（峰值）、`0x23` 按 §4.4 使能 |
| 【19】正弦扰动 | 写 `0x24=3`（周期/幅度口径见 §4.6） |
| 【12–16】装订工作点 | `CTRL[4]` 打一个脉冲：积分清零 + 输出回 `BIAS_CODE`（`host/llctl.py: bind_pi()`） |
| 【08】同步采集 | 读 `0x03`/`0x05`/`0x08`/`0x09`，或开 `0x28 STREAM_EN` |

## 6. 调试 LED

| 引脚 | 含义 |
|---|---|
| `led_heartbeat = R2` | 心跳（每个控制 tick 翻转一位，最高位最慢） |

| `CTRL[12:11]` | `led_status[1:0]` | 含义 |
|---|---|---|
| `0` | `STATUS[1:0]` | `{OTR, 光丢失}` |
| `1` | `STATUS[3:2]` | `{积分到限, 输出到限}` |
| `2` | `STATUS[5:4]` | `{ADC 时钟停摆, 冻结}` |
| `3` | `STATUS[7:6]` | `{0, 扫描完成}` |

## 7. 与 DC/AC 量程的衔接

ADC/DAC 都是 **14 位偏移二进制**，`0x2000` 是中点（0 V）。
DAC 侧 14 bit / ±5 V ⇒ 约 **0.61 mV/步**（依据 `_scratch/alientek/AN9767REV1.0.pdf`：
AD9767 电流输出 20 mA，±5 V 由 ACM9767 模块上的 I-V 级运放完成，**不在 FPGA 内**）。

⚠️ 硬件参数（IO 电平版本、输入量程/阻抗、I-V 级码↔电压直线度、
DDS 13 位振幅字 ↔ AD9767 14 位对齐）尚未全部实测确认，
统一放在 `rtl/hw_params.vh` 里，**不要在别处硬编码**。
